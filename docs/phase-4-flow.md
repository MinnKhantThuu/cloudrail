# Phase 4 — source deployment

Scope: connect a GitHub App owned by the workspace owner, choose an installation/repository/branch, then build an exact commit using Dockerfile or Railpack. Public repositories can be used before an App is configured. GitHub account installation and live signed delivery proof need the owner's account/domain.

Flow: service → Source → repository/branch/root/build settings → Save → Build & deploy → build log → immutable registry digest → existing readiness/traffic pipeline. Runtime variables remain separate from build configuration; installation credentials are never build arguments.

- App private key and webhook secret are encrypted in PostgreSQL; API shows configured status, never returns them.
- Short-lived installation tokens are generated by the API and stay in the control plane. Archive downloads use exact SHA and restrict redirects to GitHub's archive hosts.
- Validate push HMAC before parsing, enforce installation/repository/branch match, ignore deleted branches, deduplicate delivery IDs atomically with build job creation.
- Build records snapshot source settings. One build executes at a time on the existing single node. Interrupted builds resume with bounded attempts/deadline; logs are bounded and cancellation stops the BuildKit process.
- Local private registry on Docker host loopback, BuildKit UNIX socket, bounded build resources/cache. The builder is privileged on the trusted owner-operated host; this release does not execute arbitrary public customer code.
- BuildKit produces the image digest. Deployment starts only after successful publication. Build failures preserve the current release.
- Tar extraction rejects traversal, links and special files, enforces byte/file limits, and deletes source/build scratch after completion.

Evidence needed: source settings/API tests, signed delivery replay tests, real Dockerfile build/deploy, real Railpack sample, browser build logs. Live App install and webhook delivery remain explicitly pending until account access exists.

References: [GitHub App tokens](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-an-installation-access-token-for-a-github-app), [webhook validation](https://docs.github.com/en/webhooks/using-webhooks/validating-webhook-deliveries), [Railpack production flow](https://railpack.com/platforms/running-railpack-in-production).
