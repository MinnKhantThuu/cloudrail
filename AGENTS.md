# Cloudrail collaboration workflow

- Read `docs/ROADMAP.md` before planning or implementation. It is the canonical phase order and progress tracker; older M1/M2 documents are technical references.
- Follow the user's phase-by-phase workflow. Before implementation, state the selected phase/substep, scope, visible outcome and completion criteria.
- Work only within the phase or continuation scope the user has authorized. Do not silently advance to later phases because tests passed. Do not ask again for authorization already provided.
- Distinguish implemented code, recorded test evidence, current live verification, user UX review and remote deployment. Update the roadmap checkpoint when work changes those states.
- Preserve existing work. No percentage-complete claims based only on phase count. At the end of a phase, report what is done, what remains, and the next substep.
